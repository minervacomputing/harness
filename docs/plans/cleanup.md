# Plan: cleanup of the Cloudflare instance

Steps 1 to 7 ported the Django backend to `cloudflare/` and kept what users and the model see identical to Python, often to the byte. Nobody uses either version yet, so that parity buys nothing. This step removes it: the code should read as idiomatic TypeScript on the platform and its libraries, not as a translation of Python.

## Principles

- **No parity with Python.** Python's `json.dumps` spelling, Pydantic's error wording and coercions, CPython's `fromisoformat` grammar, `urllib.parse`, the `email` package, `HTMLParser`, Unicode 16 tables: all go. Behaviour follows the runtime and the libraries (`JSON.stringify`, zod's messages, `URL`, `Intl`, `postal-mime`, `htmlparser2`).
- **Security properties stay.** What a rewrite may not loosen: strict tool inputs (unknown fields refused at every depth, no prototype keys, safe integers, record-size limits), the egress checks of the Web connector (raw-host syntax checked before any parser repairs it, canonical host, public-suffix boundary including private suffixes, no IPs or special-use names, default ports, no credentials, every redirect re-checked, the exact URL sent is the one authorized), bounded decompression, mail recipients limited to granted canonical addresses (ambiguous or repaired headers refused, duplicates refused, no header injection), the redaction policies of provider HTML (Teams hides channel mentions, Teams links and quotes; Intercom hides internal links), the write ledger, the folder and zip limits, and the accounts policy.
- **No data or compatibility to keep.** Stored formats and API shapes may change. The JSON API keeps its shapes only because the frontend reads them (`{detail}`, the 422 list).
- **Tests check our behaviour, not Python's.** A test that pins what Python did is deleted, not ported. A test of authorization, request shape, error mapping, a security refusal or a durability protocol stays, with its expectation updated. Suites are never deleted by file name alone: the security invariants inside a parity suite (prototype keys, escaped JSON keys, decompression bombs, hostile hosts) are kept as small tests first.
- **Vertical changes.** A unit replaces a helper and updates all its callers in the same commit; no compatibility shims.
- **Comments say what the code does.** References to `backend/*.py`, "today's", spec section numbers and Python's behaviour go from every file a unit touches. Explanations of runtime and security behaviour stay (Cloudflare's refusal of private addresses, V8's key-escape bug).

## Findings (2026-10-12)

| Area | Size | Problem |
|---|---|---|
| Python emulation in `src/lib/` and connectors | ~7,300 lines in dedicated modules, ~800 call sites | `json.ts` (`visibleJson`), `schema.ts` and `gateway/validation.ts` (Pydantic strings and error wording), `lax.ts` and the `google`, `microsoft`, `atlassian` `model.ts` (Pydantic lax mode, alias fallback), `isoformat.ts`, `zones.ts` and five connector date modules, `urlsplit.ts`, `idna.ts`, `text.ts`'s `python*`, `casefold.ts`, `lower.ts`, `unicode.ts`, `digits.ts`, `order.ts`, `pyerrors.ts`, `htmlparser.ts`, `connectors/*/python.ts`, `linear/pyjson.ts` |
| Gmail | 2,446 lines in `connectors/gmail/email/` | A port of Python's `email` package (header parser, folding, legacy parameters, encoded words) to read addresses and compose messages |
| Parity tests | ~4,600 of 6,842 unit tests; 6.5 MB of fixtures; 23 Python generators | `*-vectors`, `*-text`, `unicode`, `text`, `coercion`, `dates`, `json`, `executor-validation`, `schema-check`-style suites compare against outputs generated by the Python backend; most connector tests load `vectors.json` from `generate.py` |
| Test time | unit 53 s wall, platform 85 s wall | Docker-backed suites run inside `test:unit` (`sandbox-local` 50 s, `conversation-local-docker` 9 s, `sandbox-python` 2 s); platform account tests hash every password with production scrypt (`frontend-auth` 55 s, `accounts-policy` 23 s) and `accounts-policy` sleeps through real rate-limit windows (`withinWindows`, up to 20 s a test) |

Considered and kept:

- **The ports around the Durable Objects** (`conversation/ports.ts`, `sandbox/ports.ts`, `lib/sql.ts`'s two adapters, `src/faults/`). They carry the fault-injection tests of the durability protocols, the hardest part of the system.
- **`lib/json.ts`'s `parseJson`.** It works around a V8 key-escape bug, not Python.
- **`pako`** in the Web connector, unless a spike in workerd shows `DecompressionStream` bounds memory during inflation (chunking, read-ahead, cancellation, bombs, damaged streams). The current inflater stops producing output at the limit.
- **Exact money** (Xero's and Stripe's decimals as text). Unit 8 may replace the hand-written decimal code with `decimal.js` (MIT) and its JSON writer with `JSON.rawJSON` if workerd has it; never floats.
- **`gateway/http.ts`** (write accounting, manual redirects, per-phase timeouts, body caps) and **`accounts/policy.ts`** (credential stamps, TOTP replay guard). Security, not parity.
- **Provider SDKs** for the connectors. Most bypass the gateway's write accounting unless they take a custom `fetch`, and they grow the bundle. Not now.
- **`contracts/`** (2,067 lines of types split from their implementations, scaffolding from the parallel build). Folding them into their owners is optional, last, if time allows.

## Units

One unit per fresh agent, in sequence, each committed on `cloudflare` after `pnpm typecheck`, `pnpm test:unit` and `pnpm test:platform` pass (and `pnpm test:docker` when a unit touches the sandbox) and opencode has reviewed the diff. Opus for units marked **security**, Sonnet otherwise.

0. **Test hygiene.** Move the Docker-backed suites to `pnpm test:docker` (own config; `test:unit` no longer needs Docker). Let platform tests hash passwords with cheap scrypt parameters, keeping a few tests on the production parameters (`needsRehash`, and the unknown-account timing test asserts that a hash runs rather than measuring time). Give the per-address and per-user rate limits an injectable clock or window length so `accounts-policy` stops sleeping. Delete the Python generators (`test/fixtures/**/*.py`) and the parity suites that test nothing else (`unicode` unit and platform, `coercion`, `contracts`, the `*-text.test.ts` suites), after moving any security invariant they hold into a small test. The `*-vectors.test.ts` suites go in their connector's unit, after it has written its own tests.
1. **Tool inputs and results (security).** `visibleJson` becomes `JSON.stringify`; `lib/schema.ts` becomes plain zod (`z.string().trim().min().max()`), without Pydantic titles, and a record helper that refuses `__proto__`, `constructor` and `prototype` keys rather than letting `z.record` drop them silently; `gateway/validation.ts` formats zod's issues in a few lines; `registry.ts` keeps its real checks (strict at every depth, safe integers, record sizes) and loses the Pydantic ones; `http/errors.ts` keeps the frontend's 422 shape with zod's messages. The parity cases of `json`, `executor-validation` and `schema` tests go; their prototype and escaped-key cases stay.
2. **Text.** `python{Strip,Split,Lower,Repr,…}`, `casefold`, `PYTHON_SPACE_CLASS`, `digits.ts`, `unicode.ts`, `lower.ts`, `order.ts` and `pyerrors.ts` become native string methods, `\s`, `\d`, `toLowerCase`, ordinary `Error` subclasses or nothing.
3. **Dates.** `isoformat.ts`, `zones.ts`, `intercom/dates.ts`, `xero/dates.ts`, `slack/times.ts`, `google_calendar/times.ts` become one small `lib/dates.ts`: RFC 3339 (with and without offset, date-only) by a strict pattern, with the calendar fields checked (no February 30th rolling into March) and offsetless times never read in the runtime's local zone; IANA time zones checked with `Intl.DateTimeFormat`. Slack's `ts` stays an exact string. `outlook_calendar/zones.ts` keeps the subset Graph documents.
4. **URLs and hosts (security).** `urlsplit.ts` becomes `URL` and `URLSearchParams`; `idna.ts` becomes the runtime's `domainToASCII` behind a raw-host syntax check (it repairs `example.com/path` and reads `127.1` as an address); `sites.ts`, `addresses.ts` and `ipaddress.ts` keep their rules (above) without Python's spellings. The security tests (IP spellings, special-use names, redirects, suffix boundaries, bombs) stay. Checkpoint: `pnpm run deploy:test` and `test/account/web-egress.test.ts` against `minerva-cf-test`.
5. **Provider answers.** `lax.ts` and the three `model.ts` become zod `z.object` schemas of what each provider actually sends (its real field names, such as Confluence's `_links` and Google userinfo's snake case), unknown fields stripped, no lax coercion, no alias fallback.
6. **HTML (security).** `htmlparser.ts` is replaced by `htmlparser2`'s tokenizer; `markdown.ts` (Web, Gmail), `teams/html.ts` and `intercom/html.ts` keep their own small policies on top of it: no images, scripts or styles, only absolute http(s) links, and the Teams and Intercom redactions, including their fail-closed handling of unclosed or self-closing elements and repeated attributes.
7. **Gmail mail (security).** Delete `connectors/gmail/email/`. Read header text with `postal-mime`'s `decodeWords` and Gmail's part tree. Reply addresses: `postal-mime`'s `addressParser` repairs broken input (it accepts `<ada@example.com` without the closing bracket), so a header is accepted only if every member is a plain address `lib/addresses.ts` canonicalizes and nothing was dropped or repaired (the header re-serialized from the parse is the header given, modulo whitespace); otherwise refused as today. Duplicate address headers stay refused and Reply-To keeps precedence. Compose with a tested library (`mimetext`, if it runs in workerd) from canonical addresses only, never a hand-written builder.
8. **Connectors**, in groups: Google (Gmail, Calendar, Drive); Microsoft (Outlook, Outlook Calendar, OneDrive, Teams); Atlassian (Jira, Confluence); Linear and Notion; Slack, GitHub and Sentry; HubSpot, Intercom, Stripe, Xero, Todoist and Web. Each removes what is left of the emulation (`python.ts`, `pyjson.ts`, Python `re` semantics in Linear's sanitizer), rewrites its tests as behaviour tests on the existing fakes with inline expectations, and only then deletes its `*-vectors.test.ts`, `vectors.json`, `runs.ts` and other generated fixtures.
9. **Docs.** Replace the plan's Python-difference sections (step 6b's lists, "Dates and time zones", "Text and number rules") with a short note pointing here; trim `cloudflare/README.md` where it explains parity.
10. **Optional: contracts.** Move each type in `src/contracts/` next to its implementation; keep only interfaces shared across Durable Objects there.

## Done when

- No code in `cloudflare/src` or `cloudflare/test` emulates Python, Pydantic or CPython, and no comment cites `backend/` (the sandbox's own Python stays).
- `test/fixtures/` holds no generated vectors.
- `pnpm test:unit` runs without Docker in well under 20 s; `pnpm test:platform` is measured before and after.
- Each unit's commit message states lines removed, tests removed and any behaviour the model or a user now sees differently.
